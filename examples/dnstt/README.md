# DNSTT: многоэтапная сборка

Адаптированный пример из GG VPN: Go-компилятор остаётся в builder, в runtime
попадают бинарный файл, Dante и tini. Домены заменены на `example.test`;
версия DNSTT и базовые образы закреплены. Конфигурация приложения и shell entrypoint
сохранены по существу из исходного проекта.

```bash
docker build -t ggvpn-portfolio-dnstt:1.0.0 examples/dnstt
docker run --rm --network none --entrypoint sh ggvpn-portfolio-dnstt:1.0.0 \
  -ec 'dnstt-server -gen-key -privkey-file /tmp/server.key -pubkey-file /tmp/server.pub; test -s /tmp/server.pub'
```

Это дополнительный пример сборки и управления процессами. Полноценное туннельное
подключение требует делегирования DNS, домена и клиента; данная подборка их
не разворачивает. Не публикуйте UDP-порт на рабочем сервере ради демонстрации.

Особенности для обсуждения:

- Dante запускается с root и понижает права рабочих процессов. Этот пример
  не демонстрирует полностью непривилегированный контейнер; основной web-стенд демонстрирует.
- SOCKS слушает только loopback, ряд частных IPv4-сетей заблокирован.
  Это не универсальная защита от всех вариантов доступа к внутренней сети.
- Периодическая ротация ключа требует обновления публичного ключа у клиентов.
  Entry point сохраняет прошлые ключи в каталоге данных — для реальной эксплуатации
  нужны правила хранения и удаления этих файлов.
- Закрепление версии и digest задаёт конкретные исходники и базы образов.
  Пакеты APT берутся из меняющегося репозитория: побитовая воспроизводимость
  образа не заявляется.

DNSTT — внешняя зависимость: [исходный проект](https://www.bamsoftware.com/software/dnstt/).
