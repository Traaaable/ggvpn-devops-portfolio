# GG VPN: фрагменты контейнеризации приложения

Это выдержки из существующего приложения, а не второй самостоятельный стенд.
Python-код, пользовательские данные, `.env`, ключи, Git history и инфраструктурные
credentials в подборку не включены. Поэтому сборка этой папки без исходного
приложения ожидаемо невозможна. Для запуска используйте основной Compose в корне.

Что показано:

- общий образ Python и отдельные роли `bot`, `web`, `worker` через `APP_ROLE`;
- установка Python-зависимостей и Ansible collections;
- данные SQLite в отдельном volume;
- `.dockerignore` с разрешённым списком файлов;
- рестарт сервисов и ограничения хранения логов.

Изменения относительно рабочего проекта:

- путь приложения заменён на `/app`;
- отсутствуют реальные домены, host gateway overrides и DNS-туннель;
- удалены монтирования Docker socket, корня хоста, SSH-ключей, Vault password,
  облачных credentials и Terraform;
- порт веб-приложения привязан к loopback;
- использован именованный volume и добавлена ротация логов.

Этот Compose показывает роли приложения. Инфраструктурные операции из веб-панели
с такой конфигурацией работать не будут: их следует выполнять отдельным
ограниченным исполнителем. Общая SQLite сохраняет связанность компонентов;
разделение процессов не означает наличие независимых микросервисов.

Dockerfile оставлен близким к исходному: build-зависимости находятся в финальном
образе, приложение запускается с root, часть Python-зависимостей не закреплена
точно. Эти ограничения не скрываются; основной runnable-пример демонстрирует
непривилегированный запуск и закреплённый базовый образ.
